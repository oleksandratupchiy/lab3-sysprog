# Навчальний компілятор Mini C

Працездатний компілятор / інтерпретатор **підмножини C**, реалізований на Python 3.11+ та PLY 3.11. Лабораторна демонструє Lex/YACC-підхід: лексичний аналіз, LALR-розбір, AST, семантичні перевірки, виконання, генерацію автономного Python та інтерактивну графіку d3.js. Реалізація функціональних бонусних критеріїв не гарантує конкретної оцінки викладача.

```text
C → PLY lex → токени → PLY yacc (LALR) → AST → семантичний аналіз
                                                 ├→ інтерпретатор
                                                 ├→ автономний Python
                                                 └→ JSON → d3.js у браузері
```

## Встановлення у Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py --help
.\.venv\Scripts\python.exe -m pytest -q
```

Активація оточення не потрібна. Якщо `py` недоступний, використайте `python -m venv .venv` з установленим Python 3.11+. У цьому середовищі `py.exe` недоступний, але готове `.venv` працює на Python 3.14.2. На Linux/macOS відповідний шлях — `.venv/bin/python`. `requirements.txt` збережено з початкового репозиторію: версії PLY, pytest та допоміжних залежностей зафіксовано. Для виконання згенерованого Python PLY не потрібний.

## Підтримувана мова

Єдина функція — `int main() { ... }`. У блоках можна оголошувати одну змінну за раз: `int x;` або `int x = expression;`. Підтримуються присвоєння `x = expression;`, десяткові цілі, змінні, дужки, унарні `+ - !`, бінарні `+ - * / %`, порівняння `== != < <= > >=`, логічні `&& ||`. Пріоритети й асоціативність відповідають C для цих операторів.

Оператори керування: вкладені `if/else`, `while`, блоки, `return expression;`, порожній оператор `;`. `else` належить найближчому незавершеному `if`. Оголошення дозволені лише в блоках, тому пишіть `if (condition) { int x = 1; }`. Підтримуються пробіли, `//` і `/* ... */`. Вхідні файли — UTF-8, допускається BOM.

Виведення обмежено **точно двома форматами**, з одним аргументом:

```c
printf("%d", expression);
printf("%d\n", expression);
```

Інші рядки, формати, виклики функцій та кілька аргументів не підтримуються.

## Правила виконання й обмеження

- Значення — довільної точності Python `int`; переповнення 32-бітного C не моделюється. Десяткові числа з початковими нулями залишаються десятковими; інших основ немає.
- `/` відкидає дробову частину до нуля без float. `%` обчислюється як `a - trunc(a/b)*b`: `-7/3 = -2`, `-7%3 = -1`.
- Нуль означає false; будь-яке ненульове значення — true. Порівняння та логічні оператори повертають саме `0` або `1`. `&&` і `||` не обчислюють непотрібний правий операнд.
- Кожний `{}` створює лексичну область. Повторне оголошення в тій самій області — помилка; затінення зовнішньої змінної дозволене. Ім'я стає видимим від свого оголошення, включно з ініціалізатором: `int x=x;` читає ще не ініціалізовану нову змінну.
- Невідомі імена, повторні оголошення та формати printf перевіряються статично, навіть у недосяжному коді. Використання неініціалізованої змінної перевіряється **під час виконання**, з урахуванням фактичної гілки й короткого замикання; статичного аналізу потоків даних немає. Оголошення в циклі щоразу скидає змінну в неініціалізований стан.
- `return` негайно завершує `main`; досягнення кінця `main` повертає `0`.
- Інтерпретатор і згенерований Python мають типовий ліміт **100000 кроків**. Крок — відвідування оператора (включно з блоком і оголошенням) або перевірка умови `while`, включно з останньою хибною перевіркою. Вирази окремо не рахуються. `--step-limit N` задає додатний ліміт, включно для генерованого файлу. Це навчальний захист від циклів, а не обмеження пам'яті чи безпечна пісочниця.
- Інтерпретатор накопичує printf у пам'яті й CLI виводить його після успішного виконання. Якщо виконання завершилося помилкою, частковий буфер не виводиться. Генерований Python друкує одразу; однакову поведінку перевірено для програм, що завершуються успішно. Для помилкових програм перевіряються категорії помилок, а не тотожність traceback або часткового виводу.
- Немає `for`, `++`, `--`, масивів, вказівників, інших типів, препроцесора, функцій користувача, присвоєння всередині виразу чи довільних expression statements. Це **не повний ISO C**. Дуже глибокі AST та надзвичайно великі числа обмежені ресурсами Python.

## CLI і приклади

```powershell
.\.venv\Scripts\python.exe main.py examples/complex.c --tokens
.\.venv\Scripts\python.exe main.py examples/complex.c --ast
.\.venv\Scripts\python.exe main.py examples/complex.c --run
.\.venv\Scripts\python.exe main.py examples/complex.c --emit-python output/program.py
.\.venv\Scripts\python.exe output/program.py
.\.venv\Scripts\python.exe main.py examples/complex.c --emit-ast output/ast.json
.\.venv\Scripts\python.exe main.py examples/complex.c --parser-report output/parser.out
```

Прапорці можна поєднувати. CLI завжди виконує розбір і статичні перевірки; без прапорців лише перевіряє програму. `--tokens` показує координати й токени, `--ast` — JSON. Батьківські каталоги вихідних файлів створюються автоматично. `output/` і таблиці діагностики не комітяться.

За `--run` stdout містить printf, stderr — окремий рядок зі значенням `main` та кількістю кроків. Код CLI: `0` за успішної обробки незалежно від C return, `1` за помилок програми/файлу, `2` за неправильних аргументів CLI. Координати помилок — рядок і стовпець, починаючи з 1; табуляція рахується як один символ. При поєднанні `--tokens` / `--ast` із `--run` у stdout також будуть ці явно запитані діагностики.

Автономний `output/program.py` має функцію `main(_step_limit=100000)`, яку можна імпортувати й отримати C return. Безпосередній запуск друкує printf, а процес Python успішно завершується з кодом 0 навіть за ненульового C return. Помилки виконання піднімають `RuntimeError` з координатами.

| Приклад | stdout (рядки) | C return |
|---|---|---|
| `examples/arithmetic.c` | `14`, `-2`, `-1` | 0 |
| `examples/conditions.c` | `1` | 5 |
| `examples/loops.c` | `120` | 0 |
| `examples/complex.c` | `-2`, `35` | 35 |

Наприклад, `loops.c` обчислює факторіал 5, а `complex.c` — суму квадратів непарних чисел 1, 3, 5, демонструє затінення `sum` та коротке замикання перед діленням на нуль.

## Інтерактивний AST

1. Виконайте команду `--emit-ast output/ast.json` вище.
2. Відкрийте `web/index.html` у сучасному браузері подвійним клацанням.
3. Натисніть «Відкрити AST JSON» і виберіть `output/ast.json`.
4. Масштабуйте коліщатком, переміщуйте дерево перетягуванням; клацайте вузли або натискайте Enter для згортання/розгортання. Наведення показує повну назву, роль, координати та унікальний ID. Кнопка «Умістити дерево» відновлює огляд.

Сторінка читає вибраний файл через `file.text()`: сервер, `fetch(file://...)` і frontend-збірка не потрібні. d3.js 7.9.0 завантажується з jsDelivr, тому потрібен інтернет, якщо скрипт не закешовано. Власний JSON не надсилається на сервер. Сторінка приймає до 10 МБ, 10000 вузлів та глибину до 200; ці обмеження стосуються переглядача, а не експорту. Кольори відрізняють структуру, керування, змінні й вирази.

## Перевірки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node --check web/app.js
```

Автоматизований набір містить **30 тестів**: лексеми, коментарі й координати; коректний/помилковий синтаксис; пріоритети й dangling else; семантичні помилки; області, ініціалізацію й затінення; вкладені цикли, return, printf, коротке замикання, великі числа й від'ємну арифметику; ділення на нуль і ліміт; JSON з унікальними стабільними ID; CLI; діагностику PLY без невирішених конфліктів.

Диференційні тести компілюють згенерований Python і запускають його в окремому процесі з timeout, порівнюючи stdout та значення `main` з інтерпретатором на 4 прикладах і 10 додаткових програмах. Окремо перевіряються помилки генерованих програм. Це підтверджує перевірені випадки, а не математично доводить еквівалентність усіх можливих програм.

Фактичні результати та браузерна перевірка зафіксовані у [docs/verification.md](docs/verification.md). Node і браузер не потрібні для pytest або роботи компілятора.
